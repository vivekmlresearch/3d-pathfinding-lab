Algorithm notes

Cost model

The grid is node-weighted: a step from u to v costs w[v], and the start cell's own weight is never paid. Walls have infinite weight. Weights are drawn from a seeded mulberry32 stream, so the same seed always rebuilds the same cube.

Heuristics

With 6 moves the hop distance is Manhattan distance, with 26 moves it is Chebyshev distance. The heuristic multiplies it by ε and by the smallest cell weight actually present. That is admissible and consistent for ε ≤ 1. Above 1 the A* variants can return a costlier path in exchange for fewer expansions.

Bidirectional search

The backward search walks reversed edges (cost of reaching u from v is w[v]). It stops when the two open-list minima add up to at least the best meeting cost, which keeps the result exact. Bi-A* uses the consistent average potential (hT − hS) / 2 so both directions share one reduced-cost graph.

What the counters mean

Expanded: nodes taken off the open list and scanned, re-expansions included. Distinct: different nodes expanded. Generated: heap insertions. Edges scanned: neighbour checks that reached an open cell. Improving relaxations: checks that lowered a label. Reopened: closed nodes put back (inconsistent heuristics only). Peak open: largest open list, summed over both directions for bidirectional runs. Working set: bytes in the typed arrays each run allocates.

Timing

Times come from performance.now() inside a Web Worker. Each algorithm gets one recorded warm-up run for the replay, then the chosen number of timed runs without recording. Allocation and initialisation of the working arrays are included. Browser timers are coarse and noisy on small cubes, so compare medians and trust expansion counts more than milliseconds.

Greedy best-first

Orders the open list by hop distance to the target only. It expands very few nodes but ignores cell cost, so the Δ column shows how far from optimal it ends up.
